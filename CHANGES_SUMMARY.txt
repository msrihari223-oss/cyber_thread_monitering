## 🔐 Security Features

1. **User Verification**
   - Users must exist in database
   - User IDs verified on both sides
   - Blocked users cannot use video calls

2. **WebSocket Security**
   - Call participants validated
   - Only authorized users can access signaling channel
   - Call IDs verified server-side

3. **Media Privacy**
   - Peer-to-peer only (no server relay)
   - Server never sees media content
   - Encrypted by browser (if HTTPS)

4. **Audit Trail**
   - All calls recorded in CallHistory
   - Call duration tracked
   - Call quality metrics stored

## 📊 Data Flow

### Making a Call:
```
1. Client A → POST /api/initiate-call → Server
2. Server creates VideoCall record (pending)
3. Server creates CallConnection
4. Client A ← Returns call_id
5. Client A establishes WebSocket connection
6. Client A creates SDP offer
7. Client A → WebSocket → Server → Client B
8. Client B receives call interface with Accept button
9. Client B → POST /api/accept-call → Server
10. Server updates status to "ongoing"
11. Client B creates SDP answer
12. Client B → WebSocket → Server → Client A
13. Both exchange ICE candidates via WebSocket
14. P2P connection established
15. Media streaming begins (P2P)
16. During call: stats monitored, chat available
17. Client ends call → POST /api/reject-call
18. Server saves CallHistory
19. P2P connection closed
```

## 📈 Performance Metrics

- **Signaling Bandwidth**: ~1-10 KB per call setup
- **Peer Connection**: 0.5-4 Mbps (variable, quality dependent)
- **Latency**: 50-500ms (depends on network)
- **CPU Usage**: 5-15% per active call (video encoder)
- **Memory**: ~50-100 MB per active call
- **Scalability**: Hundreds/thousands of concurrent calls (P2P model)

## 🐛 Known Limitations

1. **No media relay** - Requires peer connectivity (add TURN for production)
2. **No encryption** - Use HTTPS/WSS in production
3. **No call recording** - Can be added with additional service
4. **Single peer** - P2P only (group calls require SFU/MCU)
5. **Audio only** - Can extend to audio-only calls
6. **No persistence** - Call data in memory (add Redis for scaling)
